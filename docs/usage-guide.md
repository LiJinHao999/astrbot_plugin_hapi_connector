# 插件使用指南

从零开始，把手机聊天窗口变成 AI 编程会话的遥控器。本文假设你已经按[安装指南](install.md)连好了 HAPI，`/hapi list` 能看到内容。

> 所有指令仅**管理员**可用（AstrBot 配置中的 `admins_id`）。

---

## 一、五分钟上手

最常用的一套流程，从看到会话到收到结果：

```
/hapi list          看看有哪些 session
/hapi sw 1          切到 1 号 session
> 帮我修一下登录页的报错     用快捷前缀发消息
/hapi a             AI 请求权限时，一键批准
```

之后 AI 的回复、权限请求、任务完成通知都会自动推送到你当前的聊天窗口，不需要盯着屏幕等。

**几个入门要点：**

- `>` 是快捷发送前缀，等价于 `/hapi send <内容>`（发给当前会话），可在设置里改成别的字符
- `>2 内容` 可以直接发给 2 号 session，不用先切换
- 忘了指令就发 `/hapi help`，或直接用自然语言让 bot 帮你操作（需开启 LLM 工具）
- 戳一戳机器人（QQ NapCat）默认等于批准全部待审批

## 二、会话管理

### 查看与切换

| 指令 | 干什么 |
|------|--------|
| `/hapi list` | 当前窗口可见的 session（别名 `ls`） |
| `/hapi list all` | 全部 session + 全局绑定状态 |
| `/hapi sw <序号或ID前缀>` | 切换当前会话 |
| `/hapi s` | 当前会话状态（模型、权限、路径等） |
| `/hapi msg [轮数]` | 回看最近几轮对话 |

「当前会话」是**按聊天窗口记的**：群 A 切到 session 1，群 B 切到 session 2，互不影响。详细规则见[多窗口会话隔离](session-isolation.md)。

### 创建与生命周期

| 指令 | 干什么 |
|------|--------|
| `/hapi create` | 交互向导创建新会话（选机器 → 目录 → agent → 类型…） |
| `/hapi create <模板名> [目录]` | 按模板一步创建，跳过向导；目录参数可覆盖模板默认 |
| `/hapi abort` | 中断正在跑的会话（别名 `stop`） |
| `/hapi archive` | 归档 |
| `/hapi resume [序号]` | 恢复已停掉的会话 |
| `/hapi reopen [序号]` | resume 失败时的备用恢复方式 |
| `/hapi rename` / `/hapi delete` | 重命名 / 删除（删除需输入 `delete` 二次确认） |
| `/hapi clean [路径前缀]` | 批量清理已停止的会话 |

小提示：给会话发消息时，如果它已经停了，插件会**先自动尝试恢复再发送**，一般不用手动 resume。

**会话模板**：在 WebUI「交互优化 → 会话模板」把常用组合（代理 + 目录 + 机器 + 类型 + YOLO + 思考深度）存成命名模板，之后 `/hapi create 主项目` 一步创建。模板目录留空的话，创建时在命令里传：`/hapi create 主项目 /home/me/proj`。

## 三、发消息与 Focus 模式

### 几种发送方式

1. **快捷前缀**：`> 内容`（发给当前会话）、`>2 内容`（发给 2 号）
2. **完整指令**：`/hapi send <内容>`（当前会话）、`/hapi to <序号> <内容>`（指定会话）
3. **Focus 模式**：开启后连前缀都不用打，见下

发出去没反应？`/hapi retry` 重发本窗口上一条消息（记录在内存里，插件重启后清空）。

发消息时**附带图片/文件**也可以：先 `/hapi upload` 交互上传，或直接在快捷前缀 / Focus 消息里带附件（指令类 `send`/`to` 只发文本）。

### Focus 模式（专注模式）

适合「接下来一段时间我就跟这一个 session 聊」的场景：

```
/hapi focus on      开启（或发：/hapi 专注）
修一下这个 bug        ← 不带前缀，直接转发给当前 session
再跑一遍测试          ← 同上
/hapi focus off     关闭（或发：/hapi 退出专注）
```

开启后，本窗口里发的**普通消息**会直接转发给当前 session。以下内容**不会**被转发，仍按原样处理：

- `/` 开头的所有命令（`/hapi ...`、AstrBot 其他指令）
- `hapi` 开头的消息（无斜杠写法）
- 你配置的关键词别名（如 `stop`、`继续`、`退出专注`）

除此之外的内容——包括看起来像命令的裸词（如单发一句 `list 一下依赖`）——都会原样发给 AI。

几个特性：

- **窗口级开关**：只影响开启它的那个聊天窗口，其他窗口照常
- **跟随当前会话**：`/hapi sw` 切换后，Focus 转发目标也跟着变
- **持久化**：插件重启后状态还在（注意 `/hapi bind reset` 会连同 Focus 状态一起清掉）
- **WebUI 可管理**：会话管理页每个窗口标题旁有 Focus 开关，窗口列表里有 `Focus` 标签

> ⚠️ 开着 Focus 时，这个窗口就不适合闲聊了——你说的每句话都会发给 AI 会话。群聊里建议谨慎开启。

## 四、审批权限请求

AI 要执行敏感操作（跑命令、写文件等）时会推送权限请求到聊天窗口：

| 指令 | 干什么 |
|------|--------|
| `/hapi pending` | 查看待审批列表（带序号） |
| `/hapi a` | 批准全部 + 依次回答提问（别名 `approve`） |
| `/hapi allow <序号>` | 只批准某一条 |
| `/hapi deny [序号]` | 拒绝全部 / 某一条 |
| `/hapi answer [序号]` | 交互式回答 AI 的提问（选选项或自由输入） |
| 戳一戳机器人 | 执行配置的快捷动作，默认=批准全部（QQ NapCat） |

**懒人方案：**

- **忙时托管**：设置里开启后，指定时间段（如睡觉时间）内自动批准全部请求
- **超时提醒**：待审批放着没管时定期提醒，避免上游会话闲置过久失效
- **YOLO / bypassPermissions**：`/hapi perm` 把权限模式调宽，AI 就不再频繁请求（风险自担）

## 五、通知推到哪个窗口？

一条通知只会发到**一个**窗口，优先级从高到低：

1. **会话绑定窗口** —— 你在哪个窗口 `sw`/`create`/发过消息，这个 session 的通知就回哪里
2. **Agent 默认窗口** —— `/hapi bind codex` 后，没绑定的 Codex 会话通知都来这个窗口
3. **默认通知窗口** —— `/hapi bind` 设置的兜底窗口

```
/hapi bind           当前窗口设为默认通知窗口
/hapi bind claude    当前窗口收所有未绑定的 Claude 通知
/hapi bind status    查看当前路由
/hapi bind reset     清掉会话绑定（保留上面两类默认设置）
/hapi routes         查看每个会话实际推到哪
```

典型玩法：建几个只有你和 bot 的小群，一个群管一个项目，各项目通知天然分流。

推送内容多少由 `/hapi output` 控制：`silence`（只推审批等关键提醒）→ `simple`（AI 文本）→ `summary`（收尾时推最近几条）→ `detail`（全量实时）。

## 六、远程文件

| 指令 | 干什么 |
|------|--------|
| `/hapi files [路径]` | 浏览会话工作目录（`-l` 显示大小） |
| `/hapi find <关键词>` | 搜文件 |
| `/hapi download <路径>` | 把远端文件发到聊天里（别名 `dl`，限 10 MB） |
| `/hapi upload` | 交互上传：发文件 → `done` 完成 / `cancel` 取消 |

适合远程看日志、拉配置、把截图丢给 AI 分析。

## 七、会话调参

| 指令 | 干什么 |
|------|--------|
| `/hapi perm [模式]` | 权限模式（default / acceptEdits / yolo…，随 agent 不同） |
| `/hapi model [名称]` | 切模型 |
| `/hapi effort [值]` | 推理强度（不带参数可看可选列表） |
| `/hapi plan` | 开关 Plan 模式 |
| `/hapi fast [on\|off]` | Codex Fast 模式 |
| `/hapi remote` | 把会话切到 remote 托管 |

不带参数执行会列出可选项，回复序号即可，不用记枚举值。

## 八、省手指的功能

- **关键词别名**：`/hapi alias` 查看当前映射。默认自带 `stop`/`停`（中断）、`继续`（给当前会话发「继续」）、`cl`（给当前会话发 `/clear` 清上下文）、`专注`/`退出专注` 等；可在 WebUI「交互优化」页自定义，比如把 `发版` 映射成一整条指令。固定内容类映射建议用 `send` 命令（发到当前会话），而不是 `to`（需要写死序号）
- **自然语言**：开启插件的 LLM 工具后，直接说「切到 2 号会话」「帮我建一个 Claude 会话」即可；操作类工具会走审批，不怕模型乱来
- **戳一戳**：动作可配置——批准 / 看列表 / 看状态 / 中断 / 循环切推送级别

## 九、常见问题

**Q: 发了消息没反应？**
先 `/hapi list` 看连接是否正常（该指令会顺带唤醒休眠的 SSE）；再确认自己是管理员、当前窗口选了 session。

**Q: 通知跑到别的群去了？**
`/hapi routes` 看路由。多半是这个 session 绑到了别的窗口——在想要的窗口里 `sw` 一下它即可接管。

**Q: resume 失败提示没有恢复 ID？**
上游会话没来得及写入原生 ID，试试 `/hapi reopen`；仍不行只能在原机器用 CLI 恢复或新建会话。

**Q: Focus 模式开了但消息没转发？**
确认当前窗口有选中的 session（`/hapi s`），并且你发的不是 `/` 开头、`hapi` 开头或关键词别名（那些仍走原来的处理）。

**Q: 想让图片/长代码好看点？**
WebUI「交互优化」页把推送呈现改为图片模式（需安装 Pillow，页面上可一键装）。
